# TradingCanvas 项目交接文档

更新日期：2026-11-20  
主分支：`main`  
仓库：`Zhangtianpu/TradingCanvas`

## 1. 项目定位

TradingCanvas 是一个面向短线交易复盘的纯前端看板，核心目标不是自动交易，而是把每日行情、连板梯队、题材演化、情绪锚定、抱团标的、模式记录和周期总结放到同一套时间轴中，帮助用户形成可复核的判断体系。

项目数据默认保存在浏览器 `localStorage`，GitHub 只保存代码，不会同步用户本地复盘数据。更换浏览器、设备或清理站点数据前，必须先在“设置”页面导出备份。

## 2. 当前技术栈

- Vue 3 + Composition API
- TypeScript
- Pinia
- Vue Router
- Chart.js
- Vite 5
- GitHub Actions + GitHub Pages
- 手写 CSS，无第三方 UI 组件库

Node.js 20 与 GitHub Actions 部署环境一致。

## 3. 本地运行与验证

```bash
npm install
npm run dev
```

默认本地地址：

```text
http://127.0.0.1:5173/
```

提交前至少执行：

```bash
npm run build
git diff --check
```

`npm run build` 同时执行 `vue-tsc` 类型检查和 Vite 生产构建。

## 4. 部署流程

`.github/workflows/deploy.yml` 监听 `main` 分支：

1. 安装 Node.js 20；
2. 执行 `npm ci`；
3. 执行 `npm run build`；
4. 上传 `dist`；
5. 部署到 GitHub Pages。

Vite 当前使用 `base: '/'`。如果以后改为非自定义域名的仓库子路径部署，需要同步检查 Vite `base` 和 Vue Router history base。

```text
src/
├── assets/styles/global.css       全局主题、颜色与基础样式
```

3. 对应 Pinia store；
4. 导入、导出以及周期快照是否需要包含新字段。

| 路由 | 功能 |
|---|---|
| `/` | 主看板、情绪温度、大周期诊断、天梯图、折线图、锚定、抱团标的 |
| `/themes` | 题材管理 |
| `/stocks` | 个股管理与交易记录 |
| `/review` | 每日行情和情绪数据录入 |
| `/positions` | 持仓统计 |
| `/cycle-summary` | 周期总结与历史快照 |
| `/emotion-anchor` | 开盘预判、收盘核对、正确率与计分规则 |
| `/emotion-cluster` | 情绪抱团标的管理 |
| `/line-chart-manage` | 折线图显示项和均线设置 |
| `/pattern-mining` | 模式挖掘和虚拟交易记录 |
| `/trade-modes` | 交易模式、天梯图标签管理 |
| `/settings` | 数据导入、导出、清理与应用设置 |

### 6.1 连板天梯图

- 两个天梯图使用不同的本地标签覆盖数据，日期上的“中位出清”和“龙头断板”互不自动同步。
- 任意高度网格可录入标的，不受当日最高板限制。
- 天梯图上方汇总涨跌、连板、晋级、封板、锚定等每日数据。
- 下方包含抱团标的和题材梯队记录。
- 抱团标的可排序、归档、恢复，并按最早有数据日期排序。
- 题材天梯图可按日期展示题材，题材背景支持右键标记。

### 6.2 折线图

- 折线图启用项由 `stores/lineChart.ts` 管理。
- 支持普通均线和开始至今累计均线。
- 放大后使用横向滚动查看完整历史。
- 数据点悬停会显示原始值、均线值和日期标签。
- 首板家数、一进二、二进三等派生指标集中在 `composables/useEmotionMetrics.ts` 中计算。

### 6.3 情绪锚定

- 当日锚定标的可从上一条记录继承；开盘判断、收盘结果和备注会被清空。
- 开盘选择超预期、符合预期、低预期，收盘后使用同一套分级核对。
- 历史正确率和计分规则在情绪锚定页面管理。
- 保存周期总结时会快照周期内的锚定记录和计分设置。

### 6.4 情绪抱团与题材梯队

- 抱团标的按日期记录走势、涨跌幅和备注。
- 题材梯队按日期保存自由文本内容，展示层会解析题材、梯队、个数和涨停数。
- 多天题材展示可用于横向比较。
- 题材备注自动保存，文本框允许拖动调整大小。

## 7. 市场情绪温度

文件：

- `src/composables/useSentimentTemperature.ts`
- `src/components/SentimentTemperaturePanel.vue`

系统使用近 60 个交易日历史分位计算 0～100 分：

| 维度 | 权重 | 主要输入 |
|---|---:|---|
| 市场广度 | 25% | 上涨/下跌家数、全 A 涨跌幅 |
| 赚钱效应 | 25% | 涨停、首板、封板率、炸板率 |
| 接力能力 | 25% | 连板、晋级率、一进二、二进三、最高板 |
| 风险承受 | 15% | 跌停和下跌占比 |
| 量价确认 | 10% | 全 A 涨跌幅和成交量变化 |

样本少于 5 日时，历史分位会向 50 分收缩；样本完整度按最多 60 日显示。该评分是复盘辅助指标，不应直接作为买卖信号。

## 8. 周期天梯图与大周期诊断

核心文件：

- `src/components/MarketCycleLadder.vue`
- `src/composables/useCycleDiagnosis.ts`
- `src/stores/marketCycle.ts`

同时修改：

- `src/types/index.ts`
- `src/composables/useStorage.ts`
- `src/components/StairChart.vue`

### 8.1 数据模型

`MarketCycleRecord` 保存：

- 大周期名称；
- 周期载体；
- 启动和结束日期；
- 人工确认阶段；
- 按交易日保存的走势标签和备注；
- 嵌套小周期；
- 创建和更新时间。

阶段枚举：

```text
启动 → 主升 → 扩散 → 高位分歧 → 退潮 → 冰点修复
```

系统建议不会覆盖 `confirmedStage`。用户选择“跟随系统建议”时才显示自动阶段。

### 8.2 负反馈强度

计算使用近 60 日历史分位：

```text
负反馈强度 =
  炸板压力 × 25%
  + 跌停压力 × 20%
  + 封板弱化 × 15%
  + 晋级弱化 × 20%
  + 梯队衰减 × 20%
```

当日存在“中位出清”时加 6 分，存在“龙头断板”时加 8 分，最终限制在 0～100。

```text
负反馈加速度 = 今日负反馈强度 - 前3日负反馈强度均值
```

系统再结合市场情绪温度和温度变化，建议当前周期阶段。建议逻辑集中在 `suggestStage()`，调整阈值时不要直接改组件。

### 8.3 界面行为

- 周期天梯图直接嵌入第一张连板天梯图，不再作为独立看板卡片。
- 日期列、单元格宽度、10/20/30/60/全部范围以及横向滚动与连板天梯图保持一致。
- 大周期占用主轨道，小周期显示在所属大周期下方，可同时展示多个周期区间。
- 点击“+ 大周期”或空白日期建立大周期；点击“+ 小周期”建立嵌套周期。
- 点击左侧周期名称或已填充的日期区间可以再次编辑、删除。
- 点击大周期或小周期轨道内的日期格，可填写启动、主升、加速、分歧、修复、震荡、退潮等走势情况及自由备注。
- 大周期保存名称、载体、开始/结束日期和人工阶段；小周期保存所属大周期、载体和日期区间。
- 负反馈强度和加速度压缩为逐日数据带；点击“负反馈”查看完整公式，点击某日数值查看当日五项分位、事件加分和最终结果。
- 没有建立周期时，负反馈数据仍会自动显示，日期空格可直接作为周期起点。

### 8.4 当前限制

- 周期运行天数优先按已有行情记录数量计算；没有对应行情时退化为排除周末的自然日期计算，尚未接入法定节假日日历。
- 周期阶段目前是规则诊断，不是机器学习模型，也没有自动回测阈值。
- `marketCycles` 已进入应用导入/导出，但尚未加入 `CycleSummary` 的周期快照。
- 当前周期天梯图会展示可见日期范围内的全部大周期和小周期；独立的历史周期管理页面尚未建立。
- 尚未统计“小周期寿命连续缩短”“不同周期结束后的负反馈峰值”等跨周期结论。

## 9. 数据持久化

主数据键：

```text
trading-canvas-data
```

主对象类型为 `AppStorage`。`loadData()` 会把旧数据与默认结构合并，因此新增字段必须提供默认值，避免旧用户升级后页面报错。

额外 localStorage 数据主要包括：

- `dashboardModuleOrder`：看板模块顺序；
- `stairChartTags_*`：天梯图网格标签；
- `stairChartHeightCalc_*`：高度计算文本；
- `stairChartTitle_*`：自定义天梯图标题；
- `stairChartCluster_*`：天梯图抱团数据兼容项；
- `feeSettings`：手续费设置。

导出数据时 `collectExtras()` 会把这些额外键写入 `_extras`，导入时恢复。

不要随意改动已有 key。确需改名时，应增加一次性迁移并保留旧记录。

## 10. 看板模块排序

看板模块定义在 `Dashboard.vue` 的 `defaultModules`。新增模块时：

1. 添加模块定义；
2. 添加对应模板分支；
3. 导入组件；
4. 保留 `loadModuleOrder()` 的缺失模块迁移逻辑。

该迁移会把新模块插入默认相对位置，同时保留用户已有排序。

## 11. 开发约定

- 使用 `@/` 别名引用 `src`。
- 日期统一使用 `YYYY-MM-DD` 字符串，便于直接比较和排序。
- Store 写操作完成后调用自身 `persist()`，不要只修改内存状态。
- 编辑旧数据时避免整体覆盖与当前功能无关的字段。
- 计算逻辑优先放在 composable，组件负责展示和交互。
- 新数据结构必须考虑旧版 localStorage 兼容。
- 涉及天梯图时，必须分别验证普通范围、全部范围和自定义天数。
- 涉及折线图时，必须分别验证普通状态、首次放大、缩小和再次放大。

## 12. 已知技术债

1. `docs/technical.md` 是早期版本，部分目录和数据结构已过时；本交接文档优先级更高。
2. 当前没有自动化单元测试或端到端测试，主要依靠 `vue-tsc`、生产构建和浏览器手工回归。
3. 部分天梯图兼容数据仍使用独立 localStorage key，后续可逐步迁入 `AppStorage`。
4. `EmotionDaily` 字段较多，新增派生指标前应优先复用 `useEmotionMetrics.ts`，避免各组件出现不同公式。
5. 周期诊断阈值属于经验规则，后续应使用历史周期统计页面校准，而不是频繁凭单日感受修改。

## 13. 推荐后续迭代顺序

1. 将大周期诊断快照加入周期总结；
2. 新增历史大周期管理和对比页面；
3. 统计小周期寿命、修复天数和周期后半程负反馈峰值；
4. 允许在设置页调整负反馈权重和阶段阈值；
5. 为情绪指标、周期诊断和 localStorage 迁移补充单元测试；
6. 最后再考虑行情 API 或跨设备同步，避免过早引入后端复杂度。
